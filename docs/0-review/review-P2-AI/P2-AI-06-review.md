# P2-AI-06 Review — Deterministic Wallpaper Prompt Architecture (P2-AI-02 Implementation)

Source prompts: [docs/working-prompts/prompts-P2-AI-02-1.md](../docs/working-prompts/prompts-P2-AI-02-1.md) (analysis) and [docs/working-prompts/prompts-P1-AI-02-2.md](../docs/working-prompts/prompts-P1-AI-02-2.md) (implementation).

## Scope Delivered

Full implementation of the P2-AI-02 Deterministic Prompt System per the AI
Constitution ([specs/002-p2-ai-prompt-builder/AI Constitution.md](../specs/002-p2-ai-prompt-builder/AI%20Constitution.md)),
following the architecture decisions from the prior Product Review
([docs/development/reviews/P2-AI-02-1.md](../docs/development/reviews/P2-AI-02-1.md)):
a 4-component Prompt Architecture (Resolver / Builder / Validator /
Snapshot) replacing the old inline `renderPrompt()`/`buildPromptContext()`
template-substitution logic that was the confirmed root cause of the
"selected Penguin, got a Fox" bug and the missing/wrong date watermark.

This is an **architecture refactor**, not a prompt-string patch — same
input now deterministically produces the exact same prompt, mascot
identity is resolved from real catalog data (not an opaque UUID), and the
date is generated by the system in Asia/Taipei (never guessed by the
model, never UTC, never hardcoded).

## Root Cause (confirmed via code trace, not assumption)

- `buildPromptContext()`'s `variables` only included `mascotId` (a UUID) —
  never the mascot's species/appearance — so even a correctly-substituted
  template gave Gemini no actual character information.
- The fallback template (`fallback-templates.js`) had **no `{{}}`
  placeholders at all** — it was a literal meta-instruction string
  ("Generate a wallpaper prompt that includes mascot, gift, ..."), so
  `renderPrompt()` replaced nothing. Production had no seeded
  `prompt_versions` row, so this fallback was very likely what was always
  being used.
- No code path anywhere in the real generation pipeline computed the
  current date — the only date-related strings in the repo were hardcoded
  example values inside throwaway test scripts, explaining a "stuck"
  date/month.
- `luckyTheme`/`blessing` were literal `<input>`/`<textarea>` fields in
  `wallpaper.html` — direct Constitution Principle 2/11 violations
  (flagged, but intentionally **not** removed this round — see Out of Scope).

## Architecture

```
Generation Service
   → Prompt Context Resolver (queries Mascot/Gift repos, resolves Asia/Taipei date)
   → Prompt Validator (throws PromptValidationError on incomplete input)
   → Wallpaper Prompt Builder (PURE function — no DB/repo/fetch/env)
   → Prompt Snapshot (reuses existing metadata_json — no new table)
   → Provider Adapter (unchanged)
```

## New Files (Node + Deno ESM twin each)

- `js/services/wallpaper/mascot-repository.js` / `.ts` — queries the
  `mascots` catalog (`id,name,title,description` → `{species, title,
  appearance, colors:null}`). `colors` deliberately left `null` — the
  current schema has no dedicated colors column and none was fabricated.
- `js/services/wallpaper/gift-repository.js` / `.ts` — queries `gifts`
  catalog (`id,name,description`).
- `js/services/prompt/prompt-context-resolver.js` / `.ts` — the only layer
  allowed to do I/O; `resolveTaipeiDate()` uses `Intl.DateTimeFormat` with
  `timeZone: "Asia/Taipei"`, formatted `YYYY.MM.DD`.
- `js/services/prompt/wallpaper-prompt-builder.js` / `.ts` — pure function,
  `buildWallpaperPrompt(input) -> {promptText, builderVersion}`.
- `js/services/prompt/prompt-validator.js` / `.ts` — `PromptValidationError`
  on any missing required field.
- `js/services/prompt/prompt-snapshot.js` / `.ts` — `{promptSnapshot,
  contextVersion, builderVersion}`.

## Modified Files

- `js/services/wallpaper/generation-service.js` / `.ts` — removed
  `renderPrompt()`/`buildPromptContext()`; wired the new pipeline;
  `promptContextResolver` is now a required constructor dependency; added
  `PROMPT_VALIDATION_FAILED` (400) / `PROMPT_CONTEXT_FAILURE` (502) error
  paths.
- `js/services/wallpaper/generation-repository.js` / `.ts` — `metadata_json`
  gains `promptSnapshot`/`contextVersion`/`builderVersion` (existing column
  reused, no schema change).
- `supabase/functions/_shared/wallpaper-generate-handler.js` / `.ts` —
  `buildOrchestrator()` constructs the mascot/gift repositories + Prompt
  Context Resolver and injects them; `ERROR_HTTP_STATUS` extended.
- Test mocks updated across `generation-service.test.js` (7 call sites),
  `provider-resilience-integration.test.js`, and
  `wallpaper-generate-handler-resilience-wiring.test.js`'s fake Supabase
  client (added `mascots`/`gifts` tables, since the Resolver now runs
  before the provider call in every scenario).
- `scripts/verify-local.ps1` — syntax checks added for all 6 new modules.

## Testing

New: `wallpaper-prompt-builder.test.js` (determinism, required fields
present in output, pure-function contract, no fabricated colors),
`prompt-validator.test.js` (8 cases — each required field missing),
`prompt-context-resolver.test.js` (mascot/gift resolution, mascot/gift

`mascot-repository.test.js`, `gift-repository.test.js`. Plus 2 new
end-to-end tests in `generation-service.test.js` confirming: mascot not
found → `PROMPT_VALIDATION_FAILED`, and the provider receives the mascot's
actual species text (not the `mascotId` string) in the final prompt.

`.\scripts\verify-local.ps1` → **167/167 tests passing** (138 prior + 29
new), no regressions.

## Constitution Compliance

| Principle | How satisfied |
|---|---|
| P2 Prompt is internal detail | Builder fully encapsulated server-side |
| P3 Character consistency mandatory | Builder always emits an explicit Character Consistency Rules block; Resolver supplies real species/appearance |
| P5 Prompt Builder is the only assembler | `buildWallpaperPrompt()` is the sole place image prompt text is composed |
| P6 Deterministic before AI | Date generated by `resolveTaipeiDate()`, never guessed |
| P7 Structured data before free text | `WallpaperPromptInput`/`WallpaperPromptResult` are explicit object contracts |
| P8 Validate before generation | Validator runs before the Builder; incomplete input always throws |
| P9 Version everything | `builderVersion`/`contextVersion` persisted per generation |
| P10 Predictable / pure | Builder is a pure function — proven via determinism test |

## Out of Scope (explicitly not touched this round)

- Shopkeeper Context Agent (P2-AI-03) — `luckyTheme`/`blessing` are still
  accepted as caller-provided values; the Resolver does not care where they
  came from, so P2-AI-03 can plug in without touching the Builder.
- Removing `wallpaper.html`'s `#luckyTheme`/`#blessing` input fields (UI
  Workflow task) — flagged as known tech debt, intentionally deferred.
- Prompt Registry v2, Wallpaper Lifecycle.

## Known Limitations / Follow-ups

- `mascots` catalog table has no dedicated "colors" column — the Builder's
  `Colors:` line is conditionally omitted rather than fabricated. If
  Product wants explicit color descriptions in the prompt, a schema
  addition (or richer `description` authoring convention) is needed.
- Not yet deployed to Supabase; the Deno `.ts` twins have not been run
  through `deno check`/a live Edge Function invocation this session.
- Whether `prompt_versions` currently has any active row in production is
  still unconfirmed (flagged in the original P2-AI-02 analysis) — the new
  Builder no longer depends on `prompt.template` content either way, so
  this is now lower priority than before.
