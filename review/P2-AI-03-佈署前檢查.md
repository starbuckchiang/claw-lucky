## 3. Gemini 成功 / timeout / invalid output / fallback 行為

| 情境 | 程式路徑 | 結果 |
|---|---|---|
| 成功 | `generateContext()` 回傳 text → `JSON.parse` 成功 → `validateShopkeeperContext` 通過 | 回傳 `source:"ai"` |
| Timeout | `gemini-text-provider.js` 依 `AbortError`/`timeout`/408 映射為 `PROVIDER_TIMEOUT` | Agent catch 區塊捕捉 → Fallback |
| Invalid output（非 JSON / 缺欄位） | `JSON.parse` 失敗回傳 `null` → Agent 拋 `Error`；或 JSON 合法但 `validateShopkeeperContext` 拋 `ShopkeeperContextValidationError` | 兩者皆被同一個 `catch` 捕捉 → Fallback |
| Provider Failure（5xx/429/401 等） | `mapTextProviderError` 映射為對應 `NormalizedProviderError` | Agent catch 捕捉 → Fallback |

**所有失敗路徑收斂到同一個 `try/catch`，只要進入 catch 一律回傳 `createFallbackShopkeeperContext()`，絕不上拋、絕不回傳半成品。** ✅ 程式邏輯正確。

### 🔴 但發現一個關鍵的實務性風險（非程式碼 bug，是「內容」問題）

`js/services/prompt/fallback-templates.js` 目前 `daily_lucky_context` 的內容是：

```
"Generate one positive daily lucky context in Traditional Chinese with fields: lucky_theme, blessing, one_liner."
```

而且我確認 **`supabase/migrations/` 裡沒有任何一筆 `daily_lucky_context` 的種子資料**，`prompt-registry-loader.js` 的邏輯是「DB 查無 active row → 直接回傳這個 fallback template」（`if (!rows.length) return getFallbackPrompt(...)`）。

問題：這個模板要求 AI 輸出的是 **snake_case** 欄位（`lucky_theme`/`one_liner`），**完全沒有提到 `story` 和 `version`**，也沒有明確要求 camelCase schema。但 `validateShopkeeperContext()` 檢查的是 **camelCase** 的 `luckyTheme`/`blessing`/`story`/`version`。

**實務後果**：只要沒有人手動在 DB 建立正確 schema 的 active prompt row，部署後即使 `GEMINI_API_KEY` 有效、Gemini API 呼叫全部成功，AI 回傳的 JSON 也幾乎必定因為欄位名稱/缺 `story`/缺 `version` 而驗證失敗 → **每一次都靜默 Fallback**，「AI 生成 Lucky Theme」這個 P2-AI-03 的核心產品目標在正式環境會**永遠不會真正發生**（不會報錯，只是每天顯示同一組固定內容）。這正是 196 個單元測試抓不到的問題——所有 Agent 測試都是用手刻的正確 schema mock 模板，從未用真正的 `fallback-templates.js` 內容跑過。

## 5. API Key / Prompt / 敏感資料外洩風險

逐一針對新檔案的所有 log 呼叫做 `grep`：

- `shopkeeper-context-agent.js`：成功/失敗 log 只含 `{event, correlationId, source, shopkeeperVersion, durationMs}` 或 `{errorName, errorMessage, durationMs}`——**不含** `promptText`、AI 原始回應、`validateShopkeeperContext` 的 `.details.errors`。
- `gemini-text-provider.js`：log 只含 `{event, correlationId, code, message, model}`——**不含** API Key、`promptText`（`promptText` 只用來當 `contents` 送給 SDK，從未進入任何 log）。
- `index.ts`：`providerConfig.apiKey` 只用於建立 client，從未被 log；`console.log`/`console.error` 包的都是呼叫方傳入的安全欄位。

✅ **未發現 API Key / Prompt 內容 / 原始 AI 回應外洩風險。**
