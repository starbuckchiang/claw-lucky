Golden Rule

Every AI decision must increase the user's feeling that today's Lucky Wallpaper was personally created for them.

（每一個 AI 的決策，都應該提升使用者感受到「這張桌布就是今天專屬為我生成的」這種體驗。）

# AI Constitution
Version: 1.0
Project: AI Lucky Wallpaper
Status: Active
Owner: Product Team

---

# Purpose

This constitution defines the permanent principles governing every AI component within the AI Lucky Wallpaper project.

It applies to:

- Shopkeeper Context Agent
- Wallpaper Prompt Builder
- Generation Service
- Prompt Registry
- Future AI Agents
- Future Image Providers

This document is technology-independent.

Changing the image model (Gemini, OpenAI, Replicate, etc.) MUST NOT change these principles.

---

# Core Product Vision

The product is NOT an AI image generator.

The product delivers a personalized "Lucky Wallpaper" experience.

The generated image is only the final outcome.

The real product experience consists of:

1. Mascot
2. Gift
3. Shopkeeper Blessing
4. Lucky Story
5. Wallpaper

Every AI component must reinforce this experience.

---

# Principle 1
AI Serves the Product

AI exists to enhance the Lucky Wallpaper experience.

The product workflow MUST NEVER be designed around AI limitations.

Users should not be required to understand prompts, models, providers, or image generation techniques.

---

# Principle 2
Prompts Are an Internal Implementation Detail

Prompt engineering is never part of the user experience.

Users must never be asked to:

- write prompts
- understand prompts
- edit prompts

The system generates prompts automatically.

---

# Principle 3
Character Consistency Is Mandatory

The selected mascot is the primary identity.

AI MUST preserve:

- mascot species
- mascot appearance
- mascot colors
- mascot personality

The mascot MUST NOT be replaced by another animal or character.

Example:

Selected:

    Lucky Penguin

Forbidden Output:

    Fox
    Bear
    Cat
    Rabbit

Character consistency has higher priority than artistic creativity.

---

# Principle 4
The Shopkeeper Is the Storyteller

The Chameleon Shopkeeper is the narrator of the experience.

The Shopkeeper is responsible for:

- Lucky Theme
- Blessing
- Story
- Daily Fortune

Users should receive the Shopkeeper's blessing.

Users should never be required to invent their own blessing.

---

# Principle 5
Prompt Builder Is the Only Prompt Generator

All image prompts MUST be generated through the Wallpaper Prompt Builder.

Direct prompt construction is prohibited.

Forbidden:

UI
→ Gemini

Allowed:

UI
→ Prompt Builder
→ Image Provider

---

# Principle 6
Deterministic Before AI

Whenever information is known, it should be generated deterministically rather than inferred by AI.

Examples:

Generated by system:

- current date
- wallpaper size
- logo placement
- composition
- mascot identity

Generated by AI:

- blessing wording
- storytelling
- artistic rendering

---

# Principle 7
Structured Data Before Natural Language

AI components communicate using structured objects.

Preferred:

JSON
DTO
Schema

Avoid:

free-form prompt concatenation

Structured contracts improve:

- reliability
- testing
- versioning
- future migration

---

# Principle 8
Validation Before Generation

Image generation MUST NOT start unless all required information is available.

Minimum required data:

- mascot
- gift
- blessing
- lucky theme
- date watermark
- style

Missing data is an error.

Generating incomplete prompts is prohibited.

---

# Principle 9
Version Everything

Every AI artifact must have a version.

Examples:

shopkeeper-v1

wallpaper-prompt-v2

prompt-schema-v1

This enables:

- rollback
- A/B testing
- reproducibility
- debugging

---

# Principle 10
AI Should Be Predictable

The same structured input should produce equivalent prompt structures.

Prompt Builder should behave like software rather than creative writing.

Creativity belongs inside the image model.

Consistency belongs inside the Prompt Builder.

---

# Principle 11
User Experience Comes Before Model Capability

When a conflict exists between:

- exposing model capability
- improving user experience

the user experience always wins.

Example:

Incorrect:

Ask the user to type a Lucky Theme.

Correct:

The Shopkeeper generates today's Lucky Theme automatically.

---

# Principle 12
Every Wallpaper Should Tell a Story

A wallpaper is not simply an illustration.

It represents:

Today's mascot

Today's gift

Today's blessing

Today's fortune

Today's memory

Every generated wallpaper should feel unique and meaningful.

---

The standard workflow is:

User

↓

Choose Mascot

↓

Choose Gift

↓

Shopkeeper Context Agent

↓

Lucky Theme

↓

Blessing

↓

Wallpaper Prompt Builder

↓

Image Provider

↓

Wallpaper

↓

Storage

↓

Download

This workflow should remain stable even if image providers change.

---

# Future Compatibility

Future AI features should extend—not replace—the existing workflow.

Examples:

✔ Personalized blessings

✔ Seasonal events

✔ Dynamic backgrounds

✔ User preferences

✔ Multi-language support

Without changing the core experience.

---

# Definition of Success

A successful AI feature is not one that produces beautiful images.

A successful AI feature consistently delivers the feeling that:

"This wallpaper was created especially for me today."

That emotional experience is the ultimate objective of the AI Lucky Wallpaper project.
